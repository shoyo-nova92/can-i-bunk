# Import and review fixes

User approved browser libraries for PDF, Excel, and image input, all file processing local, no backend/API key. Preserve static HTML/CSS/JS and existing user data. No upload of files to remote services.

## Parallel ownership

- Parent: data.js, attendance.js, storage.js, setup.js, calendar.js, app.js, index.html, styles.css, package files/vendor preparation, core/storage tests and docs.
- File-reader agent: ONLY file-readers.js and file-readers.test.js. Export async `readTimetableFile(file,{onProgress=()=>{}}={})` -> `{text:string,warnings:string[]}`. text should preserve table columns as TABs/newlines when possible. Text/CSV input also supported. Strict file/page/pixel/sheet bounds and useful errors; never execute document scripts or formulas. Parent provides local vendor assets listed below. Scanned PDF pages use local OCR. No raw files/images persisted.
- Timetable agent: ONLY timetable.js, timetable-parser.js, timetable-parser.test.js. `parseTimetable(text)` -> `{rows:[{subject:string,day:0..6,time:'HH:MM'}],warnings:string[]}`; support row listings and common day/time grids; never guess ambiguous mappings silently. `mountTimetable(root,store)` -> `{render()}` imports readTimetableFile; drop/file chooser/paste input, extraction progress/errors, editable review of subject/day/time rows; only commit after explicit review. End date once; per discovered subject only attended and held counts. Historical counts cover the selected date AND time (default local now); generate only sessions after that cutoff to retain later classes today without double counting. totals = held + generated remaining, missed = held-attended. Show this assumption clearly and estimated totals. Prevent duplicate subjects or accidentally replacing history. Import adds new subjects atomically; existing subjects require explicit name correction/remove existing via parent's setup. Local only, safe textContent; preserve draft controls on render. Reuse generateSessions from setup.js, createSubject/createSession/data helpers. End date and nonnegative integer counts validated. No module subscriptions.
- Planner agent: ONLY planner.js and planner.test.js. Add visible per-subject calculations showing held=A+M, missed, current percent, final planned N, remaining R, planned bunks B, required75=ceil(.75N), required60=ceil(.60N), allowance=A+R-B-required75, deficit where negative, recovery attend count. Clearly distinguish current from projected. Root adds `formatPercent(value)` in attendance.js (null -> no classes held; avoid rounding across60/75); import helper. Root analyze additionally returns `attendanceSlack`, capped `allowance`, `outsideSemester`, and `statuses` keyed IDs with codes cancelled/attended/missed/unresolved/check/bunk/exceeded/required/available. Use codes rather than label text for new mandatory comparisons. Existing analyze fields remain. No English string business logic.
